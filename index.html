How Forge (Pilot Engine) Works

A plain-English walkthrough of the pipeline — what happens to your data from upload to final report, and where to look for what.

Launch Forge ↗
The Short Version: Everything runs entirely in your browser — there's no server and no database. When you click Generate Final Report, the app filters your Qualys export, matches each vulnerability to a running AWS or Azure asset by IP, enriches it with CMDB ownership data, applies your configured SLA rules, and produces a searchable report plus dashboards. Nothing is ever silently dropped — anything excluded or ambiguous is logged to the Exceptions tab with a reason.
1
Click to inspect ▾

Severity filter

Severity 1 and 2 are always removed — this is a fixed rule. Rows below your configured minimum severity (default: 3) are dropped too. Rows with a missing or invalid severity, IP, or QID are excluded and logged to Exceptions rather than silently skipped.

🛡️ Threshold Gate: Filters Sev 1/2 noise immediately; records anomalies in Exceptions Log.
2
Click to inspect ▾

Unique ID & Vulnerability ID

Every surviving row gets IP/QID as both its Unique ID and Vulnerability ID — deterministic, so the same vulnerability gets the same ID every week. This is what makes week-over-week comparison possible.

🔑 Formula: `${IP}/${QID}`. Enables delta diffing across disparate weekly scan drops.
3
Click to inspect ▾

Cloud matching (AWS → Azure)

The app builds an instant lookup of every AWS/Azure private IP up front, then checks: is this IP a running instance? If yes, CSP, Cloud Account Name and Impacted Asset (the IP itself) are filled in. Stopped/terminated instances don't count as a match — they're logged as "IP Not Running" instead.

☁️ Instance State Check: Stopped or decommissioned virtual machines flagged as IP Not Running.
4
Click to inspect ▾

CMDB enrichment — 3 tiers

To fill Application Name, APM ID, IF/PCI and ownership, the app tries IP first, then the 5-digit correlation code shared between the cloud Account/Subscription name and the CMDB's correlation field, then hostname as a last resort. First match wins; duplicates are flagged, never silently picked.

🏛️ 3-Tier Priority: Tier 1: Exact IP Match ➔ Tier 2: 5-Digit Correlation Code ➔ Tier 3: Hostname.
5
Click to inspect ▾

Vulnerability Category — self-decided

No CMDB mapping needed: each vulnerability is automatically classified as Operating System or Application by scanning Qualys's own Category, Title and OS fields for keyword signals (Windows/Linux/kernel → OS; Apache/database/browser → Application).

🏷️ Keyword Heuristic: Real-time regex scanner classifies findings into OS or Application layers.
6
Click to inspect ▾

SLA & Vulnerability Age

SLA days come from your configurable table (Critical/High/Medium × IF/PCI classification). Vulnerability Age is always today's actual date minus First Found date — recalculated fresh every time you generate, regardless of the Report Date field. Past the SLA? It's flagged Past Due SLA.

⏱️ Dynamic Clock: Calculates true calendar age from First Found date against today's runtime date.

Nothing gets silently dropped — Exception Log Categories (Click to filter)

Every exclusion or ambiguity is written to the Exceptions log with the record's IP/QID, a reason, the source system, and a plain-language detail. Severity/IP/QID failures are hard exclusions; cloud and CMDB ambiguities remain flagged in the report.
